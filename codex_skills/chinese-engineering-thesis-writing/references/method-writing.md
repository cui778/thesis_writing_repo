# 中文工科论文方法节写作

## 1. 方法节的论证任务

方法节不仅描述“怎么实现”，还要建立以下链条：

```text
现有条件或瓶颈
-> 设计需求
-> 数学/算法设计
-> 工程含义
-> 可验证假设
```

## 2. 方法模块写法

每个关键模块至少包含：

1. **设计动机**：没有该模块时会出现什么具体问题；
2. **输入输出**：张量、集合、变量、单位或维度；
3. **数学操作**：公式做了什么；
4. **工程直觉**：该操作对应什么物理或诊断过程；
5. **实现边界**：依赖哪些先验、参数和假设；
6. **验证接口**：后文哪个对比或消融验证该设计。

## 3. 公式解释

公式后不得只罗列符号。至少解释：

- 形式层：求和、归一化、注意力、损失或约束如何作用；
- 信息层：哪些信息被保留、抑制或聚合；
- 工程层：对系统响应、空间传播或诊断输出意味着什么。

不要重复用自然语言逐字翻译公式。

## 4. 对比方法

对比方法按“验证作用”组织，而非按名称堆叠：

| 对比角色 | 回答的问题 |
|---|---|
| 无空间结构 | 空间建模是否必要 |
| 常规图模型 | 普通邻接传播是否足够 |
| 单模块模型 | 单次机制是否有效 |
| 完整模型 | 模块组合是否形成增益 |
| 消融模型 | 增益来自哪一部分 |

若两个模型同时改变多项结构，不将差异归因于单一模块。

## 5. 可复现信息

方法或实验设置应覆盖：

- 数据范围与划分；
- 输入特征和预处理；
- 模型结构与关键超参数；
- 训练目标和损失权重；
- 随机种子和重复次数；
- 软件、脚本或配置入口；
- 输出与评价方式。

正文保留影响结果解释的设置；完整参数可放表格或附录。

## 6. 禁止写法

- “为了提高性能，设计了……”而不说明具体瓶颈；
- “充分利用”“有效融合”等无操作对象的表述；
- 未经消融便宣称某模块是性能来源；
- 将代码实现细节等同于方法创新；
- 用结果倒推方法设计动机。
