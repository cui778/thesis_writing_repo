# 技术路线图 S1-FIGURE-STRATEGY 图形策略

## 1. 图的角色

本图是论文总技术路线图，用于回答：

```text
工程资料如何转化为多场景数据
-> 稀疏监测条件下如何完成 I/E 缺陷诊断
-> 诊断结果如何反向支撑监测节点布局优化
```

本图不是章节目录、实验参数表、单章模型结构图或性能结果图。

## 2. 标题

建议使用：

```text
面向城市排水管网渗入与渗漏缺陷的时空诊断及监测布局优化研究
```

术语规则：

- 图内使用 `I/E 缺陷`。
- 图注首次出现时展开为“渗入/渗漏（Infiltration/Exfiltration, I/E）缺陷”。
- 不使用“入渗入流与渗漏缺陷”，避免把 `I/E` 错写为 Infiltration/Inflow。

## 3. 画幅与总体构图

### 3.1 正式版画幅

推荐：

```text
A4 纵向适配
宽高比约 3:4
单栏缩放后仍可辨认三层结构
```

设计阶段可使用较大的纵向画布，例如 `1800 × 2400 px` 或相近比例。最终排版时按论文页面宽度缩放。

### 3.2 阅读路径

采用自上而下的主阅读路径：

```text
标题
-> 第一层：仿真数据生成
-> 第二层：时空图缺陷诊断
-> 第三层：监测布局优化
-> 最终方案
```

每一层内部遵循：

```text
输入卡片
-> 技术模块
-> 中间产出
-> 向下一层交付
```

不要使用复杂回环箭头。第 4 章到第 5 章只保留一条醒目的向下桥梁箭头，表达“固定布局评价驱动布局优化”。

## 4. 三层布局

使用三个纵向堆叠的大型虚线分区。分区之间保留明显留白和居中的向下箭头。

### 4.1 第一层：SWMM 多场景仿真数据生成

推荐高度占整图约 `42%`。第一层信息较多，需要留出最大空间。

#### 顶部输入行

横向排列 6 个白色小卡片：

```text
管网拓扑资料
节点与管段属性
泵闸及调蓄设施
排水分区资料
运行调度资料
现场监测数据
```

六张卡片汇聚到：

```text
研究子区划分与管网结构概化
```

#### 中部技术模块

并排放置 3 个技术模块卡片：

| 模块标题 | 卡片内第二行 |
|---|---|
| 水力模型构建 | 动力波演算 · 边界条件 |
| 正常工况构建 | DWF 时序 · 日变化扰动 |
| 水质模型构建 | 背景输入 · 输移反应 |

三者汇聚到：

```text
SWMM 基础模型与合理性检查
```

再向下连接：

```text
PySWMM 自动化批量仿真
```

#### 下部场景分支

从 PySWMM 分叉为两个并行模块：

| 左侧 | 右侧 |
|---|---|
| 无缺陷正常工况 | I/E 缺陷场景 |
| 参照响应 · 正常扰动 | 渗入注入 · 渗漏注入 · 时间门控 |

两者汇聚到：

```text
全网节点级水力水质时序
-> 原始特征 + residual 派生特征
```

#### 第一层交付

将“原始特征 + residual 派生特征”作为向第二层交付的出口卡片。

### 4.2 第二层：水力约束时空图缺陷诊断

推荐高度占整图约 `32%`。本层是全图视觉核心。

#### 顶部输入行

横向排列 3 个白色小卡片：

```text
管网图结构
时序滑动窗口
稀疏监测掩码
```

三者共同输入核心模型：

```text
水力约束时空图诊断模型
```

#### 核心模型内部机制

核心模型不能画成空盒子。卡片内部或紧邻下方展示四步机制链：

```text
时间特征编码
-> 图结构空间聚合
-> 水力传播关联建模
-> 共享时空表征
```

其中“水力传播关联建模”使用更深的绿色或边框强调。这是诊断方法区别于一般时空图模型的关键视觉锚点。

#### 双输出与聚合

从共享时空表征分叉为：

| 左支路 | 右支路 |
|---|---|
| 窗口级活跃响应 | 节点定位评分 |
| `p_active(t)` | `node_scores(t)` |

再汇聚到：

```text
场景级诊断结果聚合
```

聚合后横向展示 3 个结果卡片：

```text
缺陷报警
活跃时段
位置 Top-K
```

#### 第二层交付与桥梁

本层底部使用一条横向评价带：

```text
固定布局诊断验证
检测评价 · 报警评价 · 定位排序评价 · 基础布局与预算敏感性
```

从该评价带中央向第三层绘制加粗向下箭头，并在箭头旁标注：

```text
诊断评价驱动布局优化
```

### 4.3 第三层：诊断导向监测布局优化

推荐高度占整图约 `26%`。

#### 顶部输入行

横向排列 3 个白色小卡片：

```text
固定诊断协议
管网响应信息
有限监测资源
```

汇聚到：

```text
监测节点布局优化
```

#### 方法演进

使用左到右的阶梯式或箭头串联式演进，避免平铺成无差别 sibling 卡片：

```text
拓扑结构布局
-> 诊断导向规则布局
-> 诊断信息驱动布局
```

卡片内允许放置较小的二级标签：

| 主卡片 | 二级标签 |
|---|---|
| 拓扑结构布局 | Degree |
| 诊断导向规则布局 | Cand-Obs · Two-stage |
| 诊断信息驱动布局 | 节点反馈 · 代理搜索 · 表征复用 |

不要在路线图中写算法版本号，例如 `v1`、`v0_2 clean` 或 `v2_2 clean`。

#### 评价与最终输出

方法汇聚到：

```text
布局性能评价与机制分析
```

下方横向排列 5 个小卡片：

```text
预算结构变化
结构可观测性
弱观测区域
I/E 分组评价
布局相似度
```

最终输出：

```text
面向缺陷诊断的监测节点优化方案
```

## 5. 模块层级

采用四级信息层级：

| 层级 | 视觉形式 | 用途 |
|---|---|---|
| L1 | 大型虚线分区 + 章节阶段标题 | 第 3、4、5 章主线 |
| L2 | 较宽技术模块卡片 | SWMM、PySWMM、诊断模型、布局优化 |
| L3 | 小型白色输入卡片或浅色结果卡片 | 输入资料、诊断结果、机制分析维度 |
| L4 | 模块内短标签 | 子步骤、方法类别和简短符号 |

模块文字规则：

- 每张卡片优先控制在一行标题和一行子标签；
- 不在卡片内写完整句子；
- 中文优先，保留必要缩写：`SWMM`、`PySWMM`、`DWF`、`I/E`、`residual`、`Top-K`；
- 仅在第二层双输出中保留 `p_active(t)` 与 `node_scores(t)`。

## 6. 箭头语义

### 6.1 主箭头

使用深灰蓝色实线单向箭头，表示数据、特征、模型输出或评价结果的传递。

### 6.2 分叉与汇聚

使用统一的细实线箭头：

- 第一层 SWMM 三模块汇聚；
- 第一层正常工况与 I/E 场景分叉、汇聚；
- 第二层双输出分叉、聚合；
- 第三层方法汇聚至机制分析。

### 6.3 强调桥梁

第 4 章到第 5 章使用一条稍粗的橙色向下箭头：

```text
固定布局诊断验证
-> 诊断评价驱动布局优化
-> 监测节点布局优化
```

### 6.4 禁止项

- 不使用双向箭头暗示尚未在论文中实现的在线闭环更新；
- 不使用循环箭头暗示自动迭代训练；
- 不把 I/E 类型分组评价画成缺陷类型分类输出；
- 不让正常工况与 I/E 场景之间出现因果箭头，二者是并行仿真分支。

## 7. 配色

整体保持论文图风格：低饱和、白底、深色文字、清晰边框。

| 区域 | 主色 | 建议色值 | 用途 |
|---|---|---|---|
| 第一层 | 蓝灰 | `#DCE8F2` / `#5E7D95` | 仿真、数据与特征 |
| 第二层 | 绿色 | `#DDEEDF` / `#4F8061` | 诊断模型与结果 |
| 第三层 | 橙色 | `#F8E5CF` / `#B8793B` | 布局优化与决策 |
| 输入卡片 | 白色 | `#FFFFFF` | 工程资料、协议与约束 |
| 中性标题条 | 浅灰 | `#EEF1F3` | 技术模块标题 |
| 主文字 | 深灰 | `#28323C` | 标题与标签 |
| 普通箭头 | 深灰蓝 | `#526574` | 主数据流 |

视觉规则：

- 大分区使用同色虚线边框和极浅底色；
- 核心模型卡片比同层其他卡片略深；
- “水力传播关联建模”使用第二层深绿色强调；
- 第 4 章到第 5 章桥梁箭头使用第三层橙色强调；
- 不使用渐变、荧光色、阴影堆叠或装饰纹理。

## 8. 图内必须展示

### 8.1 第一层

- 工程资料与现场监测；
- 研究子区划分与管网结构概化；
- SWMM 基础模型与合理性检查；
- 水力、正常工况和水质三个模型组件；
- PySWMM 自动化批量仿真；
- 无缺陷正常工况与 I/E 缺陷场景；
- 原始特征与 residual 派生特征。

### 8.2 第二层

- 管网图结构、时序窗口和稀疏监测掩码；
- 水力约束时空图诊断模型；
- 时间编码、空间聚合、水力传播关联建模和共享表征；
- `p_active(t)` 与 `node_scores(t)`；
- 场景级聚合；
- 缺陷报警、活跃时段和位置 Top-K；
- 固定布局评价与预算敏感性桥梁。

### 8.3 第三层

- 固定诊断协议、管网响应信息和有限监测资源；
- 监测节点布局优化；
- 从拓扑结构布局到诊断导向规则布局，再到诊断信息驱动布局的方法演进；
- 布局性能评价与机制分析；
- 最终监测节点优化方案。

## 9. 图注承接

图注负责解释图内不宜展开的内容：

1. `I/E` 表示渗入/渗漏（Infiltration/Exfiltration）。
2. 参照响应用于 residual 对齐，正常扰动样本用于表示合理波动并约束误报。
3. 诊断模型采用 full-graph sparse-observation：保留完整图拓扑，仅监测节点具有有效动态观测。
4. 场景级报警、活跃时段和 Top-K 排序由窗口级 `p_active(t)` 与 `node_scores(t)` 沿时间聚合得到。
5. 第三层固定诊断协议，只改变监测节点集合与 observed mask。
6. 第五章展示的是方法演进与机制分析框架，不代表未统一协议复核的方法已经形成最终性能排序。

## 10. 图内省略

- 研究区域的详细工程对象名称；
- 节点数、管段数、场景数、监测节点数；
- `IE420`、`normal20`、`degree_N25`、`lambda_loc`；
- 48 h、10 min、窗口长度和步长；
- 水质组分数量、控制方程和 residual 公式；
- 指标数值、方法排名和性能提升比例；
- `direct/near/far`、hard candidates、Jaccard、node_holdout 等英文实验术语；
- 第五章旧路径、桥接证据和待重训说明；
- 在线反馈回环或尚未实现的自动闭环优化。

## 11. S2 草图探索合同

S2 生成 4 张低保真 raster 草图，每张单独生成：

| 草图 ID | 结构方向 | 目的 |
|---|---|---|
| `SKETCH-A` | 纵向三层章节路线 | 默认方向，最适合论文页面 |
| `SKETCH-B` | 纵向三层 + 强化第 4 章诊断核心 | 检查模型机制是否足够醒目 |
| `SKETCH-C` | 纵向三层 + 强化诊断到布局优化桥梁 | 检查第 5 章承接是否清楚 |
| `SKETCH-D` | 左到右数据到决策主线，三层泳道辅助 | 作为横向备选方向 |

四张草图必须使用相同事实底座，只探索构图、密度和视觉重心差异。草图阶段允许使用简化标签，但不得遗漏：

```text
SWMM
PySWMM
I/E 缺陷场景
residual 派生特征
水力传播关联建模
场景级聚合
固定布局评价
监测节点布局优化
机制分析
```

## 12. S1 决策结论

正式版默认方向：

```text
纵向三层章节路线图
```

默认视觉重点：

```text
第一层建立数据可信度
第二层突出水力传播关联建模
第三层突出诊断评价驱动布局优化
```

默认风格：

```text
白底、低饱和配色、虚线章节分区、规整卡片、短标签、清晰箭头
```
