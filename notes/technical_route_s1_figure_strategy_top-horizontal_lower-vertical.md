# 技术路线图 S1-FIGURE-STRATEGY 修订版：上横下一纵两层布局

## 1. 修订结论

本版替代“横向画布 + 三条并排竖向泳道”策略，作为后续草图探索的正式合同。

整张图保持 `16:9` 横向画布，采用：

```text
上层：第 3 章横向数据底座
下层：第 4 章与第 5 章两条并排竖向泳道
```

这样处理的原因是：

- 第 3 章同时服务于诊断与布局优化，是全文共享的数据底座；
- 上层横向展开可容纳输入并列、模型内部并列、场景分叉与结果汇聚；
- 下层左侧突出诊断模型内部机制；
- 下层右侧突出诊断导向的布局方法演进；
- 整图不再退化为三列线性目录。

## 2. 图的角色与标题

本图是论文总技术路线图，用于回答：

```text
工程资料如何转化为可控多场景数据
-> 稀疏监测条件下如何完成 I/E 缺陷诊断
-> 诊断评价如何驱动监测节点布局优化
```

建议标题：

```text
面向城市排水管网渗入与渗漏缺陷的时空诊断及监测布局优化研究
```

术语规则：

- 图内使用 `I/E 缺陷`；
- 图注首次出现时展开为“渗入/渗漏（Infiltration/Exfiltration, I/E）缺陷”；
- 不使用“入渗入流与渗漏缺陷”。

## 3. 画幅与总体骨架

### 3.1 画幅

推荐：

```text
16:9 横向画布
设计阶段：2400 × 1350 px
```

### 3.2 空间分配

| 区域 | 内容 | 建议占比 |
|---|---|---:|
| 顶部标题区 | 总标题 | 8% |
| 上层横向泳道 | 第 3 章：SWMM/PySWMM 多场景仿真数据生成 | 34% |
| 中间交接区 | residual 特征向下交付 | 6% |
| 左下竖向泳道 | 第 4 章：水力约束时空图缺陷诊断 | 52% 高度，约 56% 下层宽度 |
| 右下竖向泳道 | 第 5 章：诊断导向监测布局优化 | 52% 高度，约 40% 下层宽度 |

下层两条泳道之间保留间距，用于绘制：

```text
固定布局评价
-> 诊断评价驱动布局优化
-> 监测节点布局优化
```

## 4. 阅读路径

### 4.1 全局路径

读者先沿上层从左到右阅读数据构建，再沿交接箭头进入左下诊断泳道，最后从左下跨入右下优化泳道：

```text
第 3 章：从左到右
-> residual 特征向下交付
-> 第 4 章：从上到下
-> 诊断评价向右交付
-> 第 5 章：从上到下
```

### 4.2 局部分支原则

- 使用并列输入、分叉与汇聚体现方法结构；
- 主流程仍然保持单向；
- 不使用反馈回环；
- 不将正常工况与 I/E 缺陷场景画成因果关系；
- 不让第 5 章反向连接第 3 章或第 4 章。

### 5.1 泳道标题

```text
SWMM/PySWMM 多场景仿真数据生成
```

使用蓝灰色虚线边界和极浅蓝灰底色。

### 5.2 左到右结构

```text

现场监测
```

两张卡片并列，汇聚到：


#### B. SWMM 基础模型

放置主模块：

```text
SWMM 基础模型

```

内部或下方展示三个并列标签：

```text
水力模型
正常工况
水质模型
```

#### C. PySWMM 自动化

```text
PySWMM 自动化
批量仿真
```

#### D. 场景分叉

| 无缺陷正常工况 | I/E 缺陷场景 |
|---|---|
| 参照响应 · 正常扰动 | 渗入 · 渗漏 · 时间门控 |

两类场景不是因果关系，应并列绘制。

#### E. 数据汇聚与交付

```text
-> 稀疏观测时空图输入
```

### 6.3 核心诊断模型

## 9. 模块层级

| 层级 | 视觉形式 | 用途 |
|---|---|---|
| L1 | 一条上层横向泳道 + 两条下层竖向泳道 | 第 3、4、5 章边界 |
| L2 | 较宽技术模块卡片 | SWMM、PySWMM、诊断模型、布局优化 |
| L3 | 小型并列、分叉和汇聚卡片 | 输入、场景、双输出、结果与机制标签 |
| L4 | 模块内短标签 | 子步骤、方法类别和必要符号 |

文字规则：

- 每张主卡片最多两行；
- 中文优先；
- 保留必要缩写：`SWMM`、`PySWMM`、`I/E`、`residual`、`Top-K`；
- 仅保留必要符号：`p_active(t)` 与 `node_scores(t)`；
- 解释性完整句子移入图注。

- 第 4 章到第 5 章的橙色桥梁是第二视觉锚点。

## 11. 图注承接

图注负责说明：

1. `I/E` 表示渗入/渗漏（Infiltration/Exfiltration）。
2. 参照响应用于 residual 对齐，正常扰动样本用于表示合理波动并约束误报。
3. 诊断模型采用 full-graph sparse-observation：保留完整拓扑，仅监测节点具有有效动态观测。
4. 场景级报警、活跃时段和 Top-K 排序由 `p_active(t)` 与 `node_scores(t)` 沿时间聚合得到。
5. 第 5 章固定诊断协议，只改变监测节点集合与 observed mask。
6. 第 5 章展示方法演进和机制分析框架，不代表尚未统一协议复核的方法已经形成最终性能排序。

## 12. 图内省略

- 节点数、管段数、场景数和监测节点数；
- `IE420`、`normal20`、`degree_N25`、`lambda_loc`；
- 采样间隔、窗口长度和步长；
- 水质组分数量、方程和 residual 公式；
- 指标数值、排名和性能提升比例；
- `direct/near/far`、hard candidates、Jaccard、node_holdout 等实验术语；
- 旧路径、桥接证据、待重训细节和执行记录；
- 尚未实现的在线反馈回环。

```text

+ 上层第 3 章横向数据底座
+ 左下第 4 章竖向诊断泳道
+ 右下第 5 章竖向优化泳道
```

```text
上层从左到右
-> residual 向下交付
-> 左下从上到下
```

```text

```
