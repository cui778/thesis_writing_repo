## 2. 统一判断

“上横下一纵”的总体方向成立，优于此前三条并排竖向泳道方案。

其优势在于：

1. 第 3 章作为共享数据底座得到横向展开空间；
2. 上层可以同时展示输入汇聚、场景分叉与数据汇聚；
3. 第 4 章能够展示输入汇聚、机制链、双输出与结果聚合；
4. 第 5 章能够展示诊断导向的布局方法演进；
5. 第 4 章与第 5 章之间的承接关系更容易形成明确视觉桥梁。

后续正式候选不再探索其他总体版式，只在该方向内优化信息密度、箭头落点、图标数量和卡片层级。

## 4. 分图评价

### 4.1 TSKETCH-A：均衡但偏平

优点：

- 区域划分规整；
- 左下诊断区的分叉与汇聚关系清楚；
- 文字密度较低；
- 适合快速重绘。

不足：

- 上层场景分叉表达较简；
- 左下模型内部的视觉锚点不够强；
- 橙色桥梁落点靠近最终监测方案，没有准确落入 `监测节点布局优化`；
- 作为总技术路线图，层次感仍稍弱。

结论：

```text
不作为主方向。
可作为正式重绘时的简洁度参照。
```

### 4.2 TSKETCH-B：数据底座最强

优点：

- 上层横向泳道表达最好；
- `工程资料` 与 `现场监测` 的汇聚清楚；
- 正常工况内部保留 `参照响应` 与 `正常扰动`；
- I/E 场景内部保留 `渗入`、`渗漏` 与 `时间门控`；
- 上层作为共享数据底座的角色最明确。

不足：

- `residual` 向下交付箭头视觉上落在右下区域边缘，需要改为进入左下 `稀疏观测时空图输入`；
- 第 4 章模型内部结构略紧凑；
- 右侧方法演进仍是直列关系，层次感弱于 D。

结论：

```text
不单独作为最终方向。
其上层数据底座表达应被主方向吸收。
```

### 4.3 TSKETCH-C：诊断模型最佳

优点：

- 左下诊断泳道最完整；
- `水力传播关联建模` 使用深绿色突出；
- 时间编码、空间聚合、水力关联与共享表征有明确内部层级；
- `p_active(t)` 与 `node_scores(t)` 双输出清楚；
- 场景级聚合与三类工程输出清楚；
- 页面尺度下仍具有较好的可读性。

不足：

- 上层 `residual` 向下箭头仍偏向右侧，没有准确落入左下输入区；
- 橙色桥梁落点靠近最终方案，不够准确；
- 右侧方法演进表达较平；
- 左下信息密度偏高，正式版需控制图标数量。

结论：

```text
保留为备选方向。
```

### 4.4 TSKETCH-D：承接关系最佳

优点：

- 上层数据底座包含必要的输入汇聚、场景分叉与输出；
- 左下诊断区保留多输入、机制链、双输出、聚合和三类结果；
- 橙色桥梁从固定布局诊断验证准确进入 `监测节点布局优化`；
- 右侧三阶方法演进最清楚；
- 机制分析标签完整；
- 三章之间的数据、证据和决策关系最接近论文总技术路线图。

不足：

- 上层 `residual` 向下箭头仍偏向右下区域，应改为进入左下输入区；
- 图标略多，正式版应减少装饰性图标；
- 右侧方法阶梯可保留，但需控制位移幅度，避免拥挤；
- 左下和右下之间的桥梁应保持突出，同时避免遮挡区域边框。

结论：

```text
推荐为主方向。
```

## 5. 主方向与备选方向

### 5.1 主方向

```text
TSKETCH-D
```

选择理由：

- 它最完整地表达“数据生成 -> 缺陷诊断 -> 布局优化”的递进关系；
- 诊断评价到布局优化的桥梁落点最准确；
- 右侧方法演进有清楚层级；
- 后续通过减少图标和修正 residual 箭头即可进入正式候选设计。

### 5.2 备选方向

```text
TSKETCH-C
```

保留理由：

- 第 4 章诊断模型内部结构表达最好；
- 水力传播关联建模具有明确视觉锚点；
- 若后续希望将论文创新重点更多放在缺陷诊断模型上，可转向该方案。

## 6. 正式候选需要吸收的优点

正式候选以 `TSKETCH-D` 为骨架，但不应机械照搬。建议吸收：

| 来源 | 吸收内容 |

| TSKETCH-C | 左下水力传播关联建模的视觉强调方式 |
| TSKETCH-D | 橙色桥梁的准确落点和右侧阶梯式方法演进 |

## 7. 进入 S4 前的硬性修订要求

正式候选合同必须明确：

1. 上层 `原始特征 + residual 派生特征` 的蓝灰色箭头向下并向左落入第 4 章 `稀疏观测时空图输入`；
