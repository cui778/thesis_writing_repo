# 技术路线图 S0-RESEARCH-FOUNDATION 事实底座

## 1. 使用范围

本报告服务于论文技术路线图，不替代章节正文、实验结果表或单章方法框架图。

技术路线图标题建议为：

```text
面向城市排水管网渗入与渗漏缺陷的时空诊断及监测布局优化研究
```

说明：

- 正文将 `I/E` 定义为渗入/渗漏（Infiltration/Exfiltration），不是通常语境中的 Infiltration/Inflow。
- 技术路线图应优先使用“渗入与渗漏缺陷”或“I/E 缺陷”，避免写成“入渗入流与渗漏缺陷”后造成概念并列混乱。
- 研究区域为武汉市黄孝河-机场河流域中划定的代表性排水管网子区。

## 2. 全文主问题

论文围绕有限监测条件下的城市排水管网 I/E 缺陷诊断展开，逐层回答三个问题：

1. 如何将工程资料转化为稳定、可控、可学习的多场景缺陷数据？
2. 如何在完整管网拓扑已知、动态观测稀疏的条件下，识别缺陷是否发生、何时活跃、优先排查哪些节点？
3. 如何在固定诊断任务和评价协议下优化有限监测节点的位置，并解释不同布局策略的作用机制与适用边界？

主线关系：

```text
工程资料与现场监测
-> SWMM/PySWMM 多场景仿真数据构建
-> 固定布局下的水力约束时空图诊断
-> 固定诊断协议下的监测节点布局优化
-> 布局性能评价、机制分析与边界说明
```

## 3. 研究区域与数据来源

### 3.1 研究区域

研究依托武汉市黄孝河、机场河水环境综合治理相关工程资料。区域中包含箱涵、明渠、泵站、闸门、截污设施、污水处理厂和调蓄单元等复杂工程对象，排水过程受到地形、下游水位、泵站运行和闸门调度共同影响。

### 3.2 建模资料

技术路线图顶部可使用以下输入卡片：

| 输入类别 | 图中短标签 | 用途 |
|---|---|---|
| 管网数据 | 管网拓扑资料 | 构建节点、管段和全网拓扑 |
| 节点与管段属性 | 节点与管段属性 | 设置高程、管径、长度、断面和糙率等属性 |
| 泵站、闸门、调蓄与河道资料 | 泵闸及调蓄设施 | 设置抽排、边界切换、蓄水单元和下游边界 |
| 排水分区与污水系统资料 | 排水分区资料 | 支撑研究子区划分和 DWF 输入 |
| 降雨、泵闸调度和运行工况 | 运行调度资料 | 辅助确定运行情景和时间序列输入 |
| 水位、流量、NH4、TSSs 等监测数据 | 现场监测数据 | 检查正常工况水力水质响应的量级与趋势 |

### 3.3 研究子区

研究子区不是对全流域的任意裁切，而是在排水分区、泵站服务范围、主干管连通关系和上下游边界约束下形成的可独立仿真单元。路线图中可画为：

```text
工程资料整理
-> 研究子区划分与管网结构概化
```

## 4. 第一层：SWMM 多场景仿真数据生成

### 4.1 本层目标

将工程资料转化为可独立运行、可批量注入缺陷、可输出节点级水力水质响应的仿真平台，并生成供第 4 章诊断模型训练与评价使用的数据基础。

### 4.2 SWMM 基线模型

图中建议保留三个并行模块：

| 模块 | 图中可见子步骤 | 作用 |
|---|---|---|
| 水力模型构建 | 动力波演算；边界条件设置 | 描述非恒定流、回水、有压流和溢流等过程 |
| 正常工况构建 | DWF 时序输入；日变化与随机扰动 | 形成动态无缺陷运行背景 |
| 水质模型构建 | 水质背景输入；输移与反应配置 | 保留水质输移背景和伴随响应 |

三者汇聚为：

```text
SWMM 基础模型与合理性检查
```

合理性检查包括：

- 结构连通性；
- 仿真稳定性；
- 边界条件合理性；
- 典型水力水质响应与现场监测趋势对比。

路线图只需展示“合理性检查”，不要写入节点数量、误差值、仿真步长和组分数量。

### 4.3 无缺陷正常工况层

无缺陷正常工况层包含两类用途：

| 类型 | 图中短标签 | 用途 |
|---|---|---|
| reference 场景 | 参照响应 | 作为逐时刻 residual 对齐基准 |
| normal 扰动样本 | 正常扰动样本 | 表征合理正常波动并约束误报 |

`reference` 与 `normal` 不是互相竞争的两套正常定义，而是同一无缺陷正常工况层中的不同用途。

### 4.4 I/E 缺陷场景

缺陷场景在同一 SWMM 基础模型和正常输入机制上叠加受控扰动：

| 缺陷类型 | 物理含义 | 典型水力响应方向 |
|---|---|---|
| I 类渗入 | 外来水或地下水进入排水系统 | 水深和出流量增加 |
| E 类渗漏 | 管网内部水量向外部环境损失 | 水深和出流量减小 |

图中保留：

```text
I/E 缺陷场景生成
渗入扰动注入
渗漏扰动注入
时间门控控制
```

### 4.5 PySWMM 自动化仿真

图中保留：

```text
PySWMM 自动化批量仿真
```

其作用是对无缺陷正常工况与 I/E 缺陷场景进行统一的时间步推进、缺陷时间门控和全网节点输出。不要在路线图中写 `IE420`、场景数量、48 h、10 min 或其他实验参数。

### 4.6 数据输出与特征构造

PySWMM 输出全网节点级水力水质时序。正式诊断特征从完整输出中按任务目标筛选，并构造 residual 派生特征：

```text
全网节点级水力水质时序数据
-> 原始特征 + residual 派生特征
```

图中可以写 `residual`，但无需展示公式。正文层面，residual 以参照响应为基准，量化缺陷场景相对于正常水平的增量变化；相对 residual 用于缓解节点间基线量级差异。

## 5. 第二层：水力约束时空图缺陷诊断

### 5.1 本层目标

在“完整管网拓扑已知、动态观测稀疏”的条件下，将连续运行场景转化为可用于工程排查的诊断结论：

```text
是否存在缺陷
+ 活跃时段
+ 候选节点 Top-K 排序
```

### 5.2 输入协议

图中保留三个输入模块：

```text
管网图结构构建
节点时序滑动窗口
稀疏监测掩码
```

核心设定是 full-graph sparse-observation：

- 图结构保留完整管网拓扑；
- 动态特征仅在监测节点上有效；
- 非监测节点使用 observed mask 屏蔽动态观测；
- 定位输出限制在具有缺陷标签支撑的候选节点空间。

### 5.3 核心诊断模型

路线图中建议将模型写为：

```text
水力约束时空图诊断模型
```

内部至少显示以下机制链：

```text
时间特征编码
-> 图结构空间聚合
-> 水力传播关联建模
-> 共享时空表征
```

其中，“水力传播关联建模”不能省略。正文中该机制对应水力逆向注意力：利用最短路径距离、路径长度、流向关系和高程差等物理路径特征，表达候选缺陷节点与监测节点之间的关联强度。

### 5.4 输出与场景级聚合

模型正式主线使用两类窗口级诊断证据：

| 输出 | 图中短标签 | 用途 |
|---|---|---|
| `p_active(t)` | 窗口级活跃响应识别 | 提供时间证据 |
| `node_scores(t)` | 窗口级节点定位评分 | 提供空间证据 |

两类证据沿时间维度聚合为：

```text
场景级诊断结果聚合
-> 缺陷报警
-> 活跃时段识别
-> 缺陷位置 Top-K 排序
```

注意：

- 场景级报警、活跃时段识别和空间定位不是三个彼此独立的模型输出头。
- 它们由窗口级 `p_active(t)` 与 `node_scores(t)` 聚合得到。
- 模型结构中的缺陷类型输出头当前不进入正式评价主线。I/E 类型分析来自按真实缺陷类型分组统计，而不是已完成的类型分类任务。

### 5.5 固定布局评价与第 5 章桥梁

第 4 章首先在固定监测布局下建立诊断基线，并分析：

```text
固定布局诊断验证
检测能力评价
场景报警评价
定位排序评价
基础布局与预算敏感性分析
```

其中，“基础布局与预算敏感性分析”是进入第 5 章的桥梁。路线图中应画出从固定布局诊断评价到布局优化的向下箭头。

## 6. 第三层：诊断导向监测布局优化

### 6.1 当前可稳定绘制的主问题

第 5 章不重新定义缺陷诊断任务。它固定第 4 章的数据、模型结构、窗口设置与评价协议，只改变监测节点集合 `S` 和对应 observed mask：

```text
固定诊断模型与评价协议
+ 管网拓扑及节点响应信息
+ 有限监测资源约束
-> 监测节点布局优化
```

### 6.2 方法演进主线

第五章虽然仍有实验结果待统一协议重训，但方法链条已经形成。技术路线图可以稳定展示方法演进，不应展示未经统一协议确认的性能优劣结论。

建议画为三层递进：

| 方法层 | 图中建议标签 | 对应方法 |
|---|---|---|
| 固定参照基线 | 拓扑结构布局 | Degree |
| 任务驱动基线 | 诊断导向规则布局 | Cand-Obs；Two-stage v1 |
| 学习型扩展 | 诊断信息驱动布局 | Node-Feedback；Surrogate-Search；Embedding-Guided |

如需减少图中文字，可将第三层内部压缩为：

```text
拓扑结构布局
-> 诊断导向规则布局
-> 诊断信息驱动布局
```

并在图注中展开：

- 候选可观测性；
- 覆盖、空间平衡与冗余控制；
- 节点级外部反馈学习；
- 布局级代理搜索；
- 诊断节点表征复用。

### 6.3 机制分析

不同布局方法汇聚到：

```text
布局性能评价与机制分析
```

图中可展示：

```text
不同预算下的结构变化
结构可观测性分析
弱观测区域识别
I/E 类型分组评价
布局相似度与空间分布
```

“不同预算下的结构变化”比“不同预算下的性能变化”更稳妥。当前尚未形成新固定协议下的完整多预算性能曲线。

### 6.4 最终产出

图中最终输出建议为：

```text
面向缺陷诊断的监测节点优化方案
```

## 7. 三层关系与箭头语义

技术路线图主箭头：

```text
工程资料与现场监测
-> 研究子区划分与管网结构概化
-> SWMM 基础模型与合理性检查
-> PySWMM 自动化批量仿真
-> 全网节点级水力水质时序
-> 原始特征 + residual 派生特征

-> 场景级诊断结果
-> 固定布局评价与预算敏感性
-> 监测节点布局优化
-> 布局性能评价与机制分析
-> 面向缺陷诊断的监测节点优化方案
```

建议明确三种箭头：

| 箭头类型 | 含义 |
|---|---|
| 实线单向箭头 | 数据、特征或结果向下游传递 |
| 分叉/汇聚箭头 | 并行模块拆分与融合 |
| 第 4 章到第 5 章的强调箭头 | 固定布局诊断现象驱动监测布局优化 |

## 9. 第五章不确定项与绘图边界

### 9.1 可直接画入路线图

- 固定诊断协议，只改变监测节点集合与 observed mask；
- 从拓扑结构布局走向诊断导向规则布局，再走向诊断信息驱动布局；
- Cand-Obs、Two-stage v1、Node-Feedback、Surrogate-Search 和 Embedding-Guided 构成方法池；
- 机制分析包含可观测性、direct/near/far、困难候选、候选覆盖、布局相似度和稳定性等维度；
- `node_holdout` 用于边界分析，不参与主排名。

### 9.2 可在图中概括，不应写成已证实结论

- “不同预算下的性能变化”应改为“不同预算下的结构变化”，除非后续完成新固定协议多预算重训；
- 学习型布局可画为方法扩展，但不要在路线图中声称其已在新协议下全面优于规则方法；
- Two-stage v1 可画为关键中间阶段，但不要在路线图中写成最终最优方案；
- 学习型布局生成多 seed 可写“结构稳定性分析”，不要写“性能稳定性已验证”。

### 9.3 暂不进入图内

- 旧 clean 路径结果；
- 旧 P3 多预算结果；
- 不同协议之间的桥接证据细节；
- 尚未统一协议复核的性能排名。
