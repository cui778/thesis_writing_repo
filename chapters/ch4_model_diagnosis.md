# 第4章 面向缺陷定位的时空图诊断模型研究

本章在第3章构建的无缺陷正常工况层和 IE420 多场景缺陷仿真数据基础上，研究固定稀疏监测布局下的排水管网 I/E 缺陷诊断与候选节点定位问题。第3章已经完成 SWMM 基础模型、正常工况生成机制、缺陷场景矩阵、批量仿真输出和残差特征构建；本章沿用同一无缺陷正常工况层，其中reference响应用于残差对齐，normal扰动样本用于表征正常波动并约束误报。随后，将连续场景数据组织为时空图学习任务，建立面向工程排查的模型训练与评价闭环。

本章采用固定 `degree N25` 监测布局。模型输入保留 128 个节点的完整管网拓扑，动态观测来自 25 个监测节点，定位输出在 50 个候选缺陷节点范围内形成排序。这里需要区分三个集合：全图拓扑节点集合 `V=128`，监测节点集合 `S=25`，候选定位节点集合 `C=50`。其中，`V` 用于表示缺陷响应传播的结构空间，`S` 用于提供稀疏动态观测，`C` 用于形成工程可排查的候选节点清单。

本章的诊断流程按照连续场景的工程排查逻辑展开：

```text
无缺陷正常工况层 + IE420 缺陷场景
→ 滑动窗口样本构建
→ 窗口级诊断证据提取
→ 场景级报警判断
→ 场景级活跃期定位
→ 场景级空间定位
→ 场景级综合诊断
→ 泛化边界与可观测性分析
```

需要强调的是，本章模型的直接输出并不是多个彼此独立的诊断头，而是窗口级 active 概率和候选节点分数。场景级报警、活跃期定位和空间定位均由这两类窗口级证据沿时间维度聚合得到。这样既保留了连续场景的时间信息，又能形成工程排查所需的“是否报警、何时异常、优先排查哪些节点”的综合结论。

## 4.1 连续场景下的缺陷诊断任务定义

### 4.1.1 工程诊断问题：是否、何时、何处

实际排水管网 I/E 缺陷诊断面对的是一段连续运行场景，而不是单个孤立时刻。给定一条48 h连续观测窗口，工程诊断通常需要回答四个相互关联的问题：该观测窗口内是否存在缺陷响应，响应大致集中在哪段时间，缺陷更可能位于哪些管网节点，以及最终应形成怎样的排查优先级。

因此，本章将诊断问题组织为五个层次。第一，窗口级诊断证据提取。模型对每个滑动窗口输出 `p_active(t)` 和 `node_scores(t)`，分别表示该窗口存在缺陷活跃响应的概率，以及候选节点的定位分数。第二，场景级报警判断。将同一 `scenario_id` 下的 `p_active(t)` 聚合为场景分数，用于判断完整48 h观测窗口是否存在缺陷。第三，场景级活跃期定位。将 `p_active(t)` 按窗口时间顺序排列，恢复缺陷大致活跃时间段。第四，场景级空间定位。在 active 时间段内聚合 `node_scores(t)`，形成该场景的候选节点排序。第五，场景级综合诊断。最终输出“是否存在缺陷 + 缺陷大致活跃时间段 + 候选节点 Top-K”。

这种任务组织方式与实际排查流程相对应。缺陷影响通常在一段时间内持续存在，单个时刻的响应可能受到流量波动和水质背景变化干扰。滑动窗口既能保留局部动态变化，又能形成可训练样本；场景级聚合则将窗口证据转化为更稳定的事件级诊断结论。上述层次是对同一组窗口级输出的不同聚合方式，并不意味着模型包含五个相互独立的输出分支。

### 4.1.2 全图拓扑、监测节点与候选定位空间

本章使用四类节点集合描述诊断边界。全网节点集合 `V` 包含 128 个节点，用于表示完整排水管网拓扑；监测节点集合 `S` 为固定 `degree N25` 布局中的 25 个节点，用于提供动态观测；候选缺陷节点集合 `C` 包含 50 个节点，是模型定位排序的输出空间；实际激活缺陷节点集合 `D` 由第3章缺陷矩阵定义，并随场景变化。

这一设置体现了排水管网诊断中的结构先验与观测约束。管网结构通常可由模型文件获得，而传感器只能布设在少数节点。模型需要在完整拓扑上建模缺陷响应传播，同时利用有限监测节点提供的动态信息完成候选节点定位。

### 4.1.3 滑动窗口与粗粒度活跃期识别

第3章构建的每个场景均对应48 h连续观测窗口。这里的48 h是统一的数据截取与评价尺度，并不等同于缺陷寿命假设；缺陷在该窗口内的活跃时段由 `start_hour` 和 `duration_h` 描述。为将连续时序转化为诊断样本，本章按 `scenario_id` 对场景分组，并采用滑动窗口生成模型输入。正式空间定位基线中，采样间隔为 10 min，`sequence_length=36`，对应约 6 h 输入窗口；`window_stride=6`，表示约每 1 h 生成一个窗口判断点。

每个窗口根据其与真实缺陷活跃时段的重叠比例生成 active 标签。窗口级 active 识别评价单个窗口是否受到缺陷影响；场景级活跃期定位评价一串窗口输出能否恢复缺陷大致发生时段。二者使用相同窗口证据，但评价层次不同。窗口级 active 准确，不必然意味着起止边界一定精确；窗口长度越长，空间响应越充分，但时间边界也越容易被平滑。

### 4.1.4 与第3章和第5章的衔接

第3章提供无缺陷正常工况层和 IE420 多场景缺陷数据，本章在固定监测布局下使用reference响应构造残差特征，并使用normal扰动样本控制正常波动下的误报，进而训练评价诊断模型；第5章则在本章诊断任务和评价协议基本固定的前提下，进一步研究监测点布局优化。三章之间形成“数据构建、固定布局诊断、布局优化”的递进关系。

对第5章而言，本章需要固定一个稳定的空间诊断基线。因此，本章正式主线仍采用 `sequence_length=36`、`window_stride=6` 的 6 h 窗口设置作为空间定位基线；较短窗口用于补充分析时间段定位能力和窗口尺度权衡。

## 4.2 稀疏观测图输入与时空诊断模型

### 4.2.1 sparse-observation 输入协议

本章采用 full-graph sparse-observation 输入协议。图结构层面保留 128 个节点及其邻接关系；动态观测层面仅保留固定 25 个监测节点的水力、水质与残差响应；同时将 observed mask 作为输入信息，使模型能够识别哪些节点具有传感器观测。

正式训练入口为 `scripts/train_privileged_teacher_student.py`。输入协议采用 full-graph sparse-observation 方式：完整管网拓扑（128个节点）始终作为图结构输入，但仅25个监测节点的动态特征作为有效观测值；非监测节点的特征通道在模型前向过程中进行掩码处理。这一设计在保留管网完整传播结构的同时，真实刻画了工程中”结构先验已知、观测信息稀疏”的实际条件，迫使模型从有限监测信号中推断全局缺陷状态。

### 4.2.2 窗口样本、active 标签与定位标签

窗口样本包含若干时间步、128 个图节点和多通道动态特征。无缺陷正常工况层中的reference窗口与normal扰动窗口，以及缺陷场景中与活跃时段重叠不足的窗口，均作为 inactive 样本；与缺陷活跃时段充分重叠的窗口作为 active 样本，并记录对应缺陷节点作为定位标签。在这一层级中，reference与normal并不是两套互相竞争的正常定义：reference提供可逐时刻对齐的参照响应，normal扰动窗口提供同一正常运行机制下的波动样本，二者共同描述无缺陷运行状态。

训练过程中，active 判断学习窗口是否受到缺陷影响，节点定位学习在 active 窗口内识别候选缺陷节点。active 识别用于提供时间证据，节点定位用于提供空间排查证据，二者共同支撑场景级诊断。

### 4.2.3 `hydraulic_inverse_deepattn` 模型结构

本章主模型为 `hydraulic_inverse_deepattn`。模型以窗口级时空图为输入，通过时序特征编码、图结构信息融合和注意力表示学习提取缺陷响应特征，并输出窗口 active 判断结果和候选节点定位分数。

该模型设计面向 I/E 缺陷的水力传播特征。缺陷注入或渗漏会改变局部节点及上下游区域的流量、水位和水质伴随响应，模型需要同时捕捉窗口内时间变化和管网拓扑中的空间关联。与仅依赖序列建模或普通图卷积的基线相比，该结构更强调水力响应、观测节点和候选定位空间之间的耦合关系。

### 4.2.4 模型输出与诊断证据

模型的诊断输出由窗口级 active 判断和节点级定位分数组成。active 判断输出 `p_active(t)`，用于刻画窗口内是否存在缺陷活跃响应；节点级定位输出 `node_scores(t)`，用于在候选节点集合中形成缺陷节点排序。二者分别对应时间证据和空间证据，并在场景级后处理中进一步聚合为活跃期定位和事件级节点定位结果。

围绕上述输出，本章将模型评价组织为窗口级证据评价和场景级诊断评价。窗口级评价关注 active 识别和候选节点排序质量；场景级评价关注同一场景内窗口证据聚合后形成的报警判断、活跃时间段和候选节点 Top-K 结果。I/E 类型差异在结果分析部分通过真实缺陷类型分组进行讨论。

## 4.3 训练协议与评价指标

### 4.3.1 训练划分与输入协议

本章主实验采用 `scenario split`，保证同一缺陷场景的窗口只出现在训练、验证或测试的一个集合中，以评价模型面对未见场景时的诊断能力。该设置对应固定候选节点空间内的场景泛化，是本章正式性能评价的主要依据。

此外，本章设置 `node_holdout` 作为泛化压力测试。该测试将部分缺陷节点从训练阶段留出，用于观察模型面对训练中未出现过的缺陷节点时的定位表现。`node_holdout` 不作为正式主性能口径，而用于说明模型的空间泛化边界。

### 4.3.2 窗口级诊断证据指标

窗口级诊断证据包括两类输出。第一类是 active 输出，其指标包括 Active F1、Normal Window FPR 和 active-period recall，用于评价真实活跃窗口是否被识别出来，以及正常窗口是否被误报为缺陷。第二类是窗口级节点定位输出，其指标包括 MRR、Top-1、Top-3 和 Top-5。MRR 反映真实缺陷节点在候选排序中的平均倒数排名，Top-K 反映真实缺陷节点进入前 K 个排查候选的比例。

窗口级指标回答的是：模型能否从单个时间窗口中提取有效诊断证据。它是后续场景级时间定位和空间定位的基础，但不是最终工程诊断结论。

### 4.3.3 场景级活跃期定位指标

场景级活跃期定位用于评价模型能否判断缺陷大致发生在哪段时间。具体做法是将同一 `scenario_id` 下的 `p_active(t)` 按窗口时间排序，根据阈值和连续窗口规则恢复预测 active 区间，并与真实 `start_hour` 和 `duration_h` 定义的 active 区间比较。

正文中建议重点报告三类指标。第一，`onset_error_hours_mean`，即预测起点与真实起点的平均小时误差。第二，`onset_accuracy_within_1/2/3_stride`，即预测起点是否落在真实起点附近 1 到 3 个滑动步长内。由于本章滑动步长固定为 1 h，三项指标分别表示起点误差不超过 1 h、2 h 和 3 h。第三，`active_interval_iou_mean`，即预测活跃区间与真实活跃区间的重叠程度。`duration_error`、`false_alarm_before_start` 和 `missed_detection` 可作为附表或备答指标。

### 4.3.4 场景级空间定位指标

场景级空间定位将同一场景内的窗口级节点分数进行聚合，形成事件级候选节点排序。常规 Event Top-K 指标回答的是：给定一个缺陷场景，模型最终能否将真实缺陷节点排入前 K 个候选节点。

需要区分两种聚合口径。第一，使用真实 active 窗口聚合的 Event Top-K，主要衡量窗口级节点分数和空间定位能力，是本章空间诊断主结果。第二，使用预测 active 时间段聚合的 scene-level Top-K，同时受到时间段定位和节点分数聚合影响，是更严格的综合诊断指标。论文主表可优先采用前者说明空间定位能力，后者用于展示完整诊断流程仍存在的改进空间。

### 4.3.5 综合诊断与分析指标

综合诊断指标同时约束时间与空间结果，例如“起点落在 ±2 窗口内且真实节点进入 Top-5”。这类指标更接近完整工程诊断流程，但也更严格，容易同时受到时间阈值、窗口长度、节点分数聚合方式影响。因此，本章将其作为审查指标和补充分析，不作为取代 MRR、Top-K 和 Event Top-K 的主评价指标。

本章还使用 I/E 分组、direct/near/far 可观测性分层和 node_holdout 压力测试解释模型表现差异。这些指标用于分析缺陷类型、候选节点与监测点拓扑距离、训练覆盖情况对定位结果的影响。

## 4.4 缺陷诊断主实验结果

### 4.4.1 窗口级诊断证据提取结果

本章首先评价模型在窗口级别提取诊断证据的能力。窗口级 active 识别用于判断当前窗口是否包含缺陷活跃响应，窗口级节点定位用于在 active 窗口内形成候选节点排序。

本章正式主实验采用“无缺陷正常工况层 + IE420缺陷层”的数据组合，实验记录中简写为 `IE420 + normal20`。其中，IE420 缺陷场景用于提供 I/E 缺陷活跃窗口和节点定位标签；normal20表示从同一正常工况生成机制得到的20个无缺陷扰动样本，用于表征正常运行波动并约束误报；reference响应则作为残差计算的统一对齐基准，不单独构成新的诊断任务。固定配置如下：

```text
dataset = 无缺陷正常工况层 + IE420缺陷层（记录名：IE420 + normal20）
feature_set = raw_plus_residual
lambda_loc = 0.5
layout = degree_N25
model = hydraulic_inverse_deepattn
```

测试集结果如下。

| 指标 | 数值 | 说明 |
|---|---:|---|
| Active F1 | 0.9790 | 窗口级缺陷活跃响应识别 |
| Normal Window FPR | 0.0005 | 正常窗口误报率 |
| Scene Recall | 0.9836 | 缺陷场景检出率 |
| Scene FPR | 0.0000 | 正常场景误报率 |
| Scene F1 | 0.9917 | 场景级报警综合指标 |
| MRR | 0.8457 | 候选节点排序整体质量 |
| Top-1 | 0.7728 | 真实缺陷节点排在首位的比例 |
| Top-3 | 0.8973 | 真实缺陷节点进入前三候选的比例 |

结果表明，在固定 `degree N25` 稀疏监测布局下，模型能够稳定识别缺陷活跃响应，并在 50 个候选节点空间内形成有效定位排序。尤其是 Normal Window FPR 仅为 0.0005，说明无缺陷正常工况层能够为模型提供正常波动范围约束，使模型在保持较高检测召回的同时有效控制误报。

建议配图：优先使用主结果表或重新绘制 `IE420 + normal20` 主结果图；模型结构多 seed 对比和主模型多 seed 稳定性结果可作为本节正式支撑图。

### 4.4.2 场景级事件定位结果

窗口级结果说明模型能够在单个 active 窗口中给出有效节点排序，但工程排查通常面对的是完整缺陷场景。因此，本章进一步将同一 `scenario_id` 下的窗口结果聚合为场景级事件定位结果。

在当前主实验中，场景级报警指标表现稳定：Scene Recall 为 0.9836，Scene FPR 为 0.0000，Scene F1 为 0.9917。这说明模型不仅能够在窗口层面识别缺陷响应，也能够通过窗口证据聚合形成可靠的场景级报警结果。

候选节点定位方面，模型取得 MRR=0.8457、Top-1=0.7728 和 Top-3=0.8973。对于工程排查而言，Top-3 指标表明模型能够在多数缺陷场景中将真实缺陷节点压缩到前三个优先排查候选，从而显著缩小人工复核范围。

本节是第4章主实验的核心结论：在第3章构建的无缺陷正常工况层和 IE420 缺陷仿真数据基础上，固定 N25 稀疏监测布局结合时空图诊断模型，能够稳定完成缺陷活跃响应识别、场景级报警和候选节点定位。

## 4.5 泛化边界、可观测性与综合分析

### 4.5.1 node_holdout 未见节点压力测试

`node_holdout` 用于评价模型面对训练阶段未出现过的缺陷节点时的表现。与 `scenario split` 相比，`node_holdout` 中 MRR、Top-1 和 Event Top-5 均明显下降，说明缺陷节点是否在训练阶段出现过，会显著影响候选节点排序质量。

该结果刻画了当前模型的空间泛化特性：模型在已知候选空间内的场景级泛化表现良好；面对训练中未出现过的缺陷节点时，诊断性能的维持需要模型具备更强的拓扑结构泛化能力，同时受益于更有利的观测布局条件。这一观察也为第5章从监测点布局角度提升诊断性能提供了直接动机。

### 4.5.3 场景级综合诊断审查

综合诊断将场景级活跃期定位与场景级空间定位同时纳入评价。使用预测 active 时间段聚合节点分数时，scene-level Top-K 会同时受到时间段选择和节点分数融合影响，因此比使用真实 active 窗口的 Event Top-K 更严格。

当前结果表明，使用窗口级 `p_active(t)` 和节点分数能够形成场景级综合诊断结果。时间段恢复依赖阈值、连续窗口规则和输入长度，因此本文将其作为粗粒度辅助分析；空间定位主结论仍优先采用真实 active 窗口聚合下的 Event Top-K。该处理方式将“空间定位能力”和“完整诊断流程表现”区分开来，也为后续优化跨窗口分数融合保留了清晰接口。

### 4.5.5 本章小结

本章围绕固定稀疏监测布局下的 I/E 缺陷诊断与候选节点定位开展研究。首先，基于第3章无缺陷正常工况层和 IE420 多场景缺陷数据建立连续场景到窗口样本的诊断任务，并明确全图拓扑、监测节点和候选定位空间之间的关系。其次，构建 `hydraulic_inverse_deepattn` 时空图诊断模型，并在 `IE420 + normal20` 主协议下取得稳定结果：Active F1 为 0.9790，Normal Window FPR 为 0.0005，Scene F1 为 0.9917，MRR 为 0.8457，Top-3 为 0.8973。结果说明，模型能够在有限监测节点条件下稳定识别缺陷响应，并有效缩小缺陷排查范围。

本章还从窗口长度、I/E 分组、`node_holdout` 和可观测性分层等角度分析模型表现。结果表明，输入窗口长度会在时间分辨率、节点排序质量和误报控制之间形成尺度差异；I 类缺陷整体定位效果优于 E 类缺陷，但两类缺陷在 Event Top-5 上均保持较高可用性；候选节点与监测节点的空间关系、训练阶段是否覆盖目标节点也会影响定位效果。上述结论为第5章从监测点布局角度提升诊断性能提供实验依据。
